**In this project your robot drives under its own code for the first time — no controller yet, just a program that makes it move and stop.**

# Part 1: How it works

## How this class does programming

You have Ollama available for this project, and every programming project after it. Use it. Describe what you want the robot to do, in plain language, and let it write the code. Iterate with it — if the first attempt doesn't work, tell it what actually happened and try again.

What you're **not** required to do is explain the code line by line. This class checks off programming work by testing it, not by reading it. If the robot does what the test below says, you're done — nobody's going to ask you to walk through the code. That's a deliberate choice, not a shortcut: the skill this class is teaching you is giving an AI clear direction and knowing how to tell if it actually did what you asked, which is a real and increasingly important skill in its own right.

That means the test matters more than usual. Read it carefully before you start, not after.

## What you're working with

Your robot's brain is the PRIZM controller — programmed in the Arduino IDE, in C++, using the `PRIZM.h` library. The pieces relevant to this project:

- `prizm.PrizmBegin()` — call this once, in `setup()`, before anything else. It stabilizes the I2C bus.
- `prizm.setMotorPowers(m1, m2)` — sets power (-100 to 100) on your two front motors, which are wired directly to the PRIZM's Motor Ports 1-2.
- If you have a four-mecanum-wheel drivetrain, your back two motors are on an I2C DC expansion module, commanded separately (something like `prizm.setMotorPower(address, motor#, power)` — the exact function name is worth confirming against your installed library rather than assuming).
- Mecanum wheels let a robot strafe sideways and rotate in place, not just drive forward/back like a tank — but that's optional territory for this project. The test below only requires forward, backward, and stopping.

Tell Ollama what hardware you're working with and what functions are available — it writes better code when it isn't guessing at your API.

## Building block by block

Don't try to get your robot doing everything at once. Get it moving forward and stopping first. Then backward. Then turning. Each of those is a small, separately-testable piece, and testing them separately is how you find out which one is broken when something doesn't work.

# Part 2: Do the work

## Step 1: Basic forward/backward

Direct Ollama to write a program that drives your robot forward for a set time or distance, then stops completely. Run it. Does it actually stop, or does it coast? A robot that doesn't fully stop can drift into things while "off."

## Step 2: Turning

Extend the program (or write a new one, your call) so the robot can turn — either a point turn (wheels spinning opposite directions) or a gentler arc. Test it in an open area with room to be wrong.

## Step 3: Put it together and pass the test

The finished program should demonstrate all of the following, back to back, in one run:

- Drives forward a measurable distance and stops completely (no coasting).
- Drives backward a measurable distance and stops completely.
- Turns (in place or in an arc) and stops.

## The test (checked at your demo)

Run your finished program once, live. It passes if:

1. The robot moves forward, stops, moves backward, stops, turns, and stops — with no manual intervention once you hit run.
2. Nothing coasts to a stop — every stop is a deliberate zero-power command, not the robot just slowing down on its own.
3. You can run it again and get the same result. A program that works once by luck doesn't pass.
