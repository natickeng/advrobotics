# Decisions

1. **2026-08-15** — advrobotics: Created PROJECT.md/DECISIONS.md to track this repo as a project thread. No content decisions yet.

2. **2026-08-15** — advrobotics: **`builder/` is the shared `rsalemiTeaches/guide-builder` submodule**, not a repo-local copy. This is the same builder `nhsengineering` pins at its own `builder/` (see that repo's DECISIONS #11, which reversed an earlier per-course-copy approach after drift caused real bugs). advrobotics pins commit `258989c` — its current `master` at setup time. Bumping the pin later means rebuilding and eyeballing any guides in both repos, per the shared builder's own rules.

3. **2026-08-15** — advrobotics: **Class format and grading model settled.** advrobotics runs as a self-directed **seminar** (Ray's term, not "survey") — 4 students, each building an individual robot, checked with 1-2 demos per 80-minute block rather than taught directly. Grading reuses nhsrobotics' existing 19/20-point checkoff system verbatim (late = points × 0.9) rather than a new rubric. There is **no per-project flex** — flex is a single, term-wide, all-or-nothing team bonus: if all four students deliver every project on time, the flex point applies to every checkoff, for everyone. (An earlier version tied each stage's flex to the newest student's progress on that same stage; that was replaced by the simpler all-four-on-time version — see the struck framing this replaces in `guides/squarebot/course.js`'s git history if it matters later.) Ray also explicitly rejected anti-takeover mentorship mechanisms (peer sign-off gates, rotating mentor schedules, mandatory explanations): "If the freshman lets someone do it for him, then so be it." Don't reintroduce policing mechanisms here unless Ray raises the concern again himself.

4. **2026-08-15** — advrobotics: **Squarebot project guides built** at `guides/squarebot/` — `p01.md` (OnShape design) through `p05.md` (autonomous movement), a shared `course.js`, and `deploy.txt` (deploys to `Class Development/Advanced Robotics/Project Guides`, matching nhsrobotics' pattern). Guides assume a **4-wheel mecanum drivetrain** (2 motors native to the PRIZM controller, 2 more via an I2C DC expansion module) — flagged in-guide as an editable assumption, unconfirmed against the actual class kit. **Pedro Pathing was considered and rejected** for the autonomous stage: incompatible hardware/toolchain (PRIZM is Arduino-class C++; Pedro Pathing needs the Android/Java FTC Control Hub). Native PRIZM C++ autonomous, closed-loop on the two encoder-equipped wheels and mirrored to the other two (valid only because the path never rotates the chassis), used instead. Student-facing guide text avoids naming Ray or using "check-in" — uses "at your demo" / generic phrasing instead, per Ray's explicit correction.

5. **2026-08-15** — advrobotics: **Deadlines mapped to the Red/Blue 2026-2027 calendar.** advrobotics meets on the same block/cycle as Robotics Red 1 — 11 R1-cycle sessions between school start and Term 1's end (2026-10-30). Pipeline stages assigned: p01 by 9/14, p02 by 9/25, p03 by 10/1, p04 by 10/7, p05 by 10/26, with 10/30 held as a demo/buffer day. Calendar itself captured from `Red Blue 2627 Calendar.xlsx` into `Technical Information/red-blue-2026-2027-schedule-calendar.md`.

6. **2026-08-15** — advrobotics: **Repo housekeeping.** Added a root `.gitignore` for `guides/**/*.pdf` and `.docx` (advrobotics had none before, unlike nhsrobotics). Found and fixed a font-substitution bug in the shared builder's code-block rendering: `Roboto Mono` (what `builder/build.js` specifies) wasn't installed in the build environment, so LibreOffice silently fell back to a non-monospace serif font instead of erroring. Fixed in-sandbox and confirmed separately on Ray's own Mac via `brew install --cask font-roboto-mono`. This is a builder/environment issue, not specific to advrobotics — worth checking for on any machine building guides for the first time.
